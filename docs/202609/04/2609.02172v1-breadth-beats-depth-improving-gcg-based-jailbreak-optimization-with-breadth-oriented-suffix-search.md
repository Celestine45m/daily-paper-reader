## 摘要
基于优化的越狱攻击（如贪婪坐标梯度（GCG））通过在白盒源模型上优化对抗性后缀，实现了强大的有效性和可迁移性。然而，现有的基于GCG的方法依赖于平均对抗损失和深度贪婪搜索，这可能会过度强调易于越狱的行为，并忽略后缀空间中有前景的区域。我们提出了BOSS，一个即插即用的框架，通过面向广度的后缀搜索来改进基于GCG的越狱优化。BOSS使用尾部聚焦对抗损失（TFAL）、标准源损失和行为覆盖来选择终止后缀，然后探索多个短轨迹，并有选择地继续有前景的后缀。在公共基准上的实验表明，BOSS在多种基于GCG的方法上提高了攻击成功率，同时减少了优化时间。

## Abstract
Optimization-based jailbreak attacks such as Greedy Coordinate Gradient (GCG) achieve strong effectiveness and transferability by optimizing adversarial suffixes on white-box source models. However, existing GCG-based methods rely on averaged adversarial loss and deep greedy search, which can over-emphasize easy-to-jailbreak behaviors and overlook promising regions of the suffix space. We propose BOSS, a plug-and-play framework that improves GCG-based jailbreak optimization through breadth-oriented suffix search. BOSS uses Tail-Focused Adversarial Loss (TFAL), standard source loss, and behavior coverage to select terminal suffixes, then explores multiple short trajectories and selectively continues promising suffixes. Experiments on public benchmarks show that BOSS improves attack success rates across multiple GCG-based methods while reducing optimization time.

- 大语言模型（LLM）即使经过安全对齐，仍容易受到手工构造或自动化生成的“越狱”提示词攻击；其中基于优化的方法（如 GCG）通过在**白盒源模型**上优化对抗后缀，再迁移到目标模型，被认为效果好、可迁移性强。
- 论文指出现有 GCG 类方法存在两大系统性缺陷：
  - **平均对抗损失不可靠**：现有方法在多个有害行为上取平均目标token的负对数似然作为损失。越狱优化不同于分类任务——已经成功越狱的行为的目标序列损失并不会归零，导致“easy behavior 一直消耗优化预算，而真正难的 hard behavior 得不到充分优化”。
  - **深度贪心搜索存在盲区**：GCG 总沿着当前 loss 最低的单条轨迹深挖，但“当前源损失低”的后缀不一定通向“最终攻击效果最好”的后缀；大量中间候选没有被继续探索就被丢弃，使最终保留的后缀常常不如搜索过程中出现过的更优后缀。
- 总体含义：本文主张在同等预算下把资源从“深度贪心搜索”转移到**广度探索**上。作者提出 BOSS（Breadth-Oriented Suffix Search）框架，对现有 GCG 类方法是**正交、即插即用**的增强方案。

## 2. 方法论：核心思想与关键技术细节

BOSS 的核心思想是分三个阶段进行“广度优先”搜索：

**（1）源侧诊断指标**

- **Tail-Focused Adversarial Loss（TFAL，尾聚焦对抗损失）**：对每个候选后缀，取出每行为损失中最高的 ⌈qh·|Xtr|⌉ 个行为（论文默认 qh=0.5），在该“难行为尾部”上平均损失。动态地强调未能成功越狱的困难行为。
- **行为覆盖率（Behavior Coverage）**：给定源损失阈值 τc，统计训练有害行为中损失低于该阈值的比例。
- **行为覆盖作为门控**：只有覆盖率不低于当前池中最大值减 δc（容差）的后缀，才能进入可行集 F(A)。
- **排序得分**：对可行集中的后缀，将标准源损失与 TFAL 各自做最小-最大归一化后，用加权和
  score = λs × Lsrc类标准化值 + λh × Lhard类标准化值
  进行排序（论文设置 λs=0.45、λh=0.20）。

**（2）三阶段搜索流程**

- **初始池构建**：运行 N 条互相独立的短轨迹（T1=30 步），得到初始终止后缀集合 A1={z₁,...,zN}。
- **父后缀选择**：在 A1 上计算覆盖率与 TFAL，筛选出可行集 F(A1)，按排序得分选取 K 个最优后缀作为 parent（默认 K=4、N=10）。若可行集不足 K 个，则从集合外按同一分数补足。
- **父后缀延续与最终选择**：对每个父后缀继续优化 T2=50 步得到 A2；对 A1∪A2 的合并集合重新计算覆盖率与 TFAL 选出最终后缀 z⋆ 送入目标模型评估。

**（3）与既有 GCG 式优化的关系**

- BOSS 不改变本地优化器的更新规则（坐标梯度近似筛选候选、批内全损失评估并取最优者更新），只是改变“只有一条轨迹能存活、中途候选全部被弃”的预算分配方式——完整算法见论文 Algorithm 1，描述清晰且可复现。

- **性能收益显著**：

  - I-GCG 平均 T-ASR 从 52.7% 提升至 69.3%；
  - GJO 平均 T-ASR 从 59.1% 提升至 71.6%；

- **效率收益**：同等预算下运行时间减半以上，来源是“多短轨迹+只延续被选父后缀”的预算再分配。
- **目标响应一致性提升**：BOSS 多数模型上提升了 BERTScore-F1，使迁移后的响应更像完整的“Step 1”式目标响应，而非仅仅绕过拒绝；定性案例也表明原 GCG 转移不稳定（有的模型拒绝、有的半跟随），而 BOSS 的后缀跨模型更稳定。

## 8. 缺点与局限性（批判性评估）

尽管论文论证完整、实验扎实，以下几点不足仍需客观指出：

- **计算前提相对苛刻**：BOSS 要求用户掌握受害白盒模型的全部梯度与 logits。虽然在“源=目标”的转移式威胁模型中成立，但对 API-only 攻防而言无能为力；论文并未讨论后续的近似梯度、代理梯度或无需梯度的扩展方向。
- **基准与目标模型覆盖面仍有提升空间**：所有主实验均基于 HarmBench 框架下的“真实有害行为 + Step-1 式目标”的标准回应模板；未覆盖“多轮式越狱”“多语言越狱”或“越狱如编码辅助的安全绕过”等其他叙事类型，即使这些类型并不妨碍本文与基线做公平对比。
- **仅评估固定后缀长度的迁移攻击**：默认后缀长度恒为 20，未探讨后缀长度的敏感性，若长度同为 20 的父辈在两个方向（更短/更长）上的表现不如其所言，或会造成一定的框架应用盲区。
- **目标模型选择或可解释空间有限**：闭源模型验证结果（表 5）多为单一代表性模型，因为 API 限制只能抽样式评测，却未计算总查询量或报价成本，难以判断“查询受限”的扩展边界对论文结论的影响程度。
- **附录中统计数据有占位符问题**：表 4 中的标准差标注为人工填写占位符，这是多个结果中不应存在的疏漏，应在审稿阶段被纠正。
- **选择指标的阈值敏感性与可调参数个数较多**：TFAL 尾部比例、覆盖率阈值与容差、两项得分权重、N/K/T1/T2 等自由参数合计超过 5 个，论文只对 N 做了系统调节，其余默认值缺乏稳健性分析，无法排除参数敏感性对优势的影响。

## 结语

BOSS 的可贵之处不在于将某一种越狱工具做到极致，而在于从底层调度层面反思“什么才算真正有效的搜索”，并在不依赖更多计算资源的前提下实现了显著改进。它以清晰的叙述、干净的控制变量设计和丰富实验证据，成为后续在多目标迁移攻击、对抗后缀合成乃至安全评测的一般流程中完全可以作为可复现候选引入的一课经典。不同目标的攻击者与防御者均可在其“覆盖优先”的启发下改进其自定义算法设计。
（完）
