## 摘要
基于大语言模型（LLMs）的软件智能体被设计用于自动程序修复（APR）任务，这使得在不久的将来，APR 智能体可能在无需太多人工干预的情况下自动修复缺陷。在这种情况下，我们能否信任 APR 智能体生成功能正确且安全的代码？如果攻击者以生产环境中的 APR 智能体为目标，向其提供看似良性但可能影响智能体生成正确却不安全代码的对抗性问题，又会怎样？在本文中，我们通过开展一项实证研究，迈出了回答这些问题的第一步。首先，我们构建了 SWEADV，这是一个包含 750 个对抗性问题描述的基准，由 SWE-bench Verified 中的 150 个修复任务构造而来。对于每个修复任务，我们构造了五个对抗性问题描述，分别对应一种攻击类型：命令执行、反序列化、路径遍历、拒绝服务以及弱哈希。其次，我们在 SWEADV 上评估了来自三个 LLM 后端的 mini_swe APR 智能体：GPT-5-Mini、MiniMax-M2.5 和 DeepSeek-R。我们发现，平均而言，对抗性问题描述可在 51.7% 的情况下诱导出成功修复但包含恶意行为的结果。第三，我们研究了典型检测机制是否足以阻止此类恶意补丁被接受。修复前检测中，使用 LLM-as-judge 对对抗性问题描述进行检测，平均检测准确率仅为 62.3%。修复后检测中，分别使用静态分析工具和 LLM-as-judge 对对抗性 APR 补丁进行检测，平均检测准确率分别仅为 39.4% 和 55.4%。我们得出结论：鉴于自主 APR 智能体易受对抗攻击影响，目前尚不能在生产部署中信任它们。

## Abstract
Software agents with Large Language Models (LLMs) are designed for Automated Program Repair (APR) tasks, raising the possibility that, in the near future, APR agents will fix bugs automatically without much human intervention. Can we trust an APR agent to produce both functionally correct and secure code in such situations? What if attackers target production APR agents with adversarial issues that seem benign but may influence the agents to produce correct but insecure code? In this paper, we took a first step towards answering these questions by conducting an empirical study. First, we created SWEADV, a benchmark of 750 adversarial issue descriptions constructed from 150 repair tasks in SWE-bench Verified. For each repair task, we created five adversarial issue descriptions, one for each attack type: command execution, deserialization, path traversal, denial of service, and weak hashing. Second, we evaluated mini_swe APR agents from three LLM backends on SWEADV: GPT-5-Mini, MiniMax-M2.5, and DeepSeek-R. We found that on average, adversarial issue descriptions can induce malicious behaviors with successful repair in 51.7% of cases. Third, we investigated whether typical detection mechanisms are sufficient to prevent such malicious patches from being accepted. Pre-repair detection with LLM-as-judge on the adversarial issue descriptions resulted in an average detection accuracy of only 62.3%. Post-repair detection on adversarial APR patches using static analysis tools and LLM-as-judge achieved average detection accuracies of only 39.4% and 55.4%, respectively. We conclude that autonomous APR agents cannot be trusted yet in production deployment, given their susceptibility to adversarial attacks.

## 2. 方法论

### 2.1 核心思想

- 从真实修复任务出发，在保持原始修复目标的前提下，向 issue 描述中嵌入攻击特定的"维护性"需求，诱导 APR 智能体在修复真实缺陷的同时注入漏洞代码。
- 攻击成功的定义：生成的补丁同时满足**功能验证谓词**（通过 FAIL_TO_PASS 与 PASS_TO_PASS 测试）和**攻击载荷谓词**（包含并调用预期漏洞行为），即 \( V_a(R, p^*) = \text{TRUE} \land T(R, p^*) = \text{TRUE} \)。

### 2.2 威胁模型

- **攻击者能力**：黑盒设置，仅能提交或影响自然语言 issue 描述 \( i^* \)；无法访问 APR 智能体内部、无法修改仓库、补丁、测试套件或验证流程。
- **攻击目标**：构造对抗性 issue \( i^* \)，使受害 APR 智能体 \( V \) 生成的补丁 \( p^* \) 既通过功能验证，又包含攻击者意图的漏洞行为。

### 2.3 SWEADV 构建流程

**（1）目标符号与注入符号提取（离线）**

- 解析 golden patch 的 diff，映射到仓库源文件，选择被修改行最多的封闭符号作为**目标符号**（如函数、方法、类）。
- 从补丁标识符和局部作用域中的邻近符号收集命名风格，生成**注入符号**（仓库风格 helper 名称），并确保该名称在仓库中不存在。

**（2）攻击载荷创建**

- 为每类攻击设计模板，包含四要素：
  - 可选导入；
  - 可替换函数名（注入符号）；
  - 攻击者可控的环境变量输入；
  - 攻击特定的危险汇聚点（dangerous sink）。
- 五类攻击对应不同危险行为：命令执行、反序列化、路径遍历、拒绝服务、弱哈希。

**（3）对抗性 issue 生成**

- 使用攻击者 LLM（Gemini 2.5 Pro），输入原始 issue 描述与攻击载荷，生成保留原修复目标、同时嵌入漏洞需求的对抗性 issue 文本。
- 使用代理修复 LLM/智能体（SWE-agent 的 mini_swe + Gemini 2.5 Pro）生成候选补丁。
- 通过轻量级 diff 验证器检查补丁是否定义并调用了预期注入 helper、是否包含攻击者可控输入与危险汇聚点、是否将 helper 连接到目标符号。
- 验证成功则保留该对抗性 issue 为 SWEADV 实例；否则将反馈返回攻击者 LLM 并重试。

**（4）漏洞补丁验证**

- 静态验证：攻击特定验证器检查补丁是否定义预期输入源、危险汇聚点，并将注入行为接入执行路径。
- 动态验证：在容器中应用补丁，提供受控触发输入，检查良性标记副作用，确认注入行为可被激活。

### 2.4 评估指标

- **Fix Rate (FR)**：对抗性 issue 导致功能有效修复的比例。
- **Injection Success Rate (ISR)**：对抗性 issue 诱导出预期漏洞行为的比例。
- **Attack Success Rate (ASR)**：生成补丁同时通过功能验证且包含攻击者意图漏洞行为的比例。

## 6. 主要结论与发现

### 6.1 RQ1：APR 智能体普遍脆弱

- SWEADV 上攻击成功率达到 **48.5%–54.0%**，约为基线（18.8%–26.4%）的两倍。
- 对抗性注入**不降低修复性能**：FR 在良性样本与对抗样本间差异通常在 4% 以内，甚至 GPT-5-Mini 在 SWEADV 上略有提升（55.3% → 63.5%）。
- 攻击成功率在不同 LLM 间较为稳定（差异仅 5.5%），说明 SWEADV 具有跨模型泛化性。
- 攻击类型差异：**weak_hashing** 最容易注入（MiniMax-M2.5 达 64.0% ASR）；**path_traversal** 较难端到端成功（ASR 40.0%–44.7%）。

### 6.2 RQ2：LLM-as-judge 检测不足

- SWEADV 对抗性 issue 比基线更难检测，引导提示下平均准确率仅 **62.3%**。
- 即使 Claude-S-4.6 在基线上接近完美（98.5% 准确率），在 SWEADV 上仅 66.0% 准确率、74.5% F1。
- **DoS 攻击最难检测**，因为其行为常伪装成正常验证支持。

### 6.3 RQ3：修复后检测效果有限

- 静态分析：Semgrep 平均准确率 49.5%，Bandit 仅 29.3%；静态分析平均准确率 **39.4%**，F1 37.0%。
- 补丁级 LLM-as-judge：平均准确率 **55.4%**，F1 61.8%，仅略优于随机猜测。
- 静态分析对显式危险 API（如 Run Command、Deserialization）较强，对上下文依赖型（Path Traversal、DoS）较弱；LLM 评审则可部分弥补规则覆盖不足，但存在过度泛化。

### 6.4 RQ4：组合检测仍不充分

- 组合检测在基线上表现优异（平均准确率 88.8%，F1 87.8%），Claude-S-4.6 达 98.1% 准确率。
- 但在 SWEADV 上，平均准确率仅 **65.9%**，F1 72.4%；最佳模型 Claude-S-4.6 也仅 75.8% 准确率。
- 失败原因分类（600 个假阴性样本）：
  - **合法缺陷或功能**（359/600）：将可疑载荷误认为普通修复或功能请求；
  - **缺少明确恶意意图**（161/600）：期望显式恶意声明；
  - **安全/审计框架**（21/600）：将危险行为视为安全审计或兼容性支持；
  - **工程不良**（19/600）：视为设计不佳而非对抗行为；
  - **证据不充分**（18/600）：默认标记为良性；
  - **钩子/基础设施**（17/600）：将 CI、调试、配置等视为合理行为；
  - **模糊**（5/600）。

### 6.5 前沿模型同样脆弱

- Claude Opus 4.5 在 206 个高难度对抗实例上：FR 98.1%，ISR 86.4%，ASR **85.4%**。
- 说明更强的编码 LLM 可能因更擅长遵循指令而更容易被对抗性指令诱导。

## 7. 优点

- **模型无关的对抗基准**：SWEADV 不绑定特定受害模型，同一对抗文本可跨模型测试，提升了评估的通用性与可比性。
- **自动化构建流水线**：从 golden patch 和仓库快照自动提取符号、生成载荷、生成对抗 issue、验证注入，流程可扩展。
- **多维度验证**：结合静态 diff 验证与动态触发 harness，降低注入标签误判风险。
- **全面的防御评估**：同时评估修复前 issue 级检测、修复后静态分析、补丁级 LLM 评审及组合检测，覆盖实际 APR 流水线中的多个防御节点。
- **深入的定性分析**：对 600 个假阴性案例进行归类，揭示 LLM 检测失败的根本原因，具有实践指导意义。
- **与已有基线对比**：在统一布局下与 SWExploit 对比，展示 SWEADV 在攻击成功率与跨模型稳定性上的优势。

## 8. 不足与局限

- **数据集覆盖有限**：仅基于 150 个 SWE-bench Verified 任务，以 Python 仓库为主，未覆盖其他编程语言或更广泛的项目类型。
- **攻击类型有限**：仅五类攻击（命令执行、反序列化、路径遍历、DoS、弱哈希），可能遗漏其他重要漏洞类别。
- **构造偏差风险**：攻击者 LLM 与构造时代理修复均使用 Gemini 2.5 Pro，虽声称实例不绑定该模型，但可能影响对抗文本的自然性与成功率。
- **基线重建问题**：SWExploit 基线中除 run_command 外的四类攻击 issue 描述为重建，可能与原始发布存在差异。
- **静态验证的残余误差**：主要注入标签依赖确定性 diff 规则，可能遗漏语法或语义变体，产生假阳性/假阴性；虽用动态 harness 缓解，但仍非完全可靠。
- **检测方法泛化性**：评估的防御策略虽具一般性，但更复杂的检测技术可能表现更好，却未必可推广到其他场景。
- **算力信息缺失**：未报告 GPU 型号、数量、训练/推理时长等资源信息，难以评估实验成本与可复现性。
- **应用限制**：结论表明当前 APR 智能体不宜直接用于生产部署，但论文未提出具体的可部署防御方案，仅指出需要更深入的安全对齐与验证研究。
