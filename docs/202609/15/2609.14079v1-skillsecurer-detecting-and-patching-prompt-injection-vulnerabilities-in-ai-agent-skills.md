## 摘要
智能体技能通过可复用的指令、脚本和配置扩展了 AI 智能体，但也容易受到新型攻击，这些攻击可影响智能体的决策与行动。为应对这些风险，我们提出 SkillSecurer，一个完全智能体化的框架，用于生成、检测、定位和修复智能体技能中的安全风险。其红方智能体在九种威胁类型中生成上下文兼容的注入，同时记录确切的修改；其蓝方智能体分析完整的技能包，生成有依据的证据，并提出补丁。对于受控实例，验证器将发现结果和补丁与记录的注入进行比较，从而实现注入级别的评估。我们通过选择最佳后端 LLM、与竞争者比较，并人工交叉验证每个评估阶段，对 SkillSecurer 进行了全面评估。在其性能最佳的后端下，SkillSecurer 是唯一实现 100% 注入检测率的扫描器。接下来，我们分析了来自 skills.sh 的热门技能，发现所检查的技能中有超过 17% 存在潜在漏洞。通过测试其中一些技能，我们触发了实际事件，表明运行未经验证的技能存在风险。我们的结果表明，上下文感知的 LLM 分析可以提供可靠的注入定位和可操作的修复方案，而不仅仅是对技能层面进行标记。

## Abstract
Agent skills extend AI agents with reusable instructions, scripts, and configuration, but are also open to new attacks to influence an agent's decisions and actions. To address these risks, we present SkillSecurer, a fully agentic framework for generating, detecting, localising, and remediating security risks in agent skills. Its red agent generates context-compatible injections across nine threat types while recording the exact modification; its blue agent analyses complete skill packages, produces grounded evidence, and proposes patches. For controlled instances, a verifier compares findings and patches with the recorded injection, enabling injection-level evaluation.   We thoroughly evaluate SkillSecurer by selecting the best backend LLM, comparing it with competitors, and manually cross-validating each evaluation stage. With its best performing backend, SkillSecurer is the only scanner to achieve a 100% injection detection rate. Next, we analyse popular skills from skills.sh, finding latent vulnerabilities in more than 17% of the skills examined. Testing some of those skills, we trigger actual incidents, showing the risks of running unverified skills. Our results show that context-aware LLM analysis can provide reliable injection localisation and actionable remediation beyond skill-level flagging alone.

- **现有工作三大缺陷**：
  - **Benchmark 层面**：多为手工策划或固定模板/简单注入/特定对抗策略生成，且**多数不记录确切的注入指令、文件或代码片段**，无法验证检测器是否正确定位漏洞。
  - **扫描器层面**：围绕静态检查、专用检测器或漏洞专用 LLM prompt 组织，输出通常是二值或粗粒度风险分类，**一般不提供任何修复方案**。
  - **评估层面**：普遍只报告技能级分类指标（是否至少报出一个发现），无法区分发现针对的是受控注入还是技能中本就存在的无关内容。
- **核心诉求**：需要一个**保留显式 ground truth、超越技能级分类、支持自动扩展新技能-威胁实例**的评估与防护框架。

## 2. 方法论

### 2.1 总体架构（全智能体框架）

SkillSecurer 由三个组件构成，其中只有 BLUE PATCHER 是部署时组件，另两者仅用于受控评估：

- **BLUE PATCHER（蓝队，部署组件）**：
  - 输入：Skill under Test（SUT）的**静态快照**，不执行不可信代码。
  - 第一遍分析输出结构化发现报告 D，每条发现含：安全类别与严重性、解释、**引用证据片段（quoted evidence span）**、在技能中的位置。
  - **证据接地（grounding）校验**：每个引用片段必须能映射回提交的 SUT 快照，否则丢弃，以防幻觉。
  - 若 D 非空，第二遍生成补丁 P，要求最小改动、移除/中和风险行为、保留合法内容。
  - 形式化：`B_detect(SUT)=D`，`B_patch(SUT,D)=P`，`B(SUT)=(D,P)`；若 D=∅ 则 P=SUT。
  - **关键隔离**：BLUE PATCHER 不接收良性对照技能、注入规格或任何 ground truth。

- **RED INJECTOR（红队，仅评估用）**：
  - 给定良性技能 S 与威胁类型 τ∈T（**九类**威胁），生成修改后技能 S′ 及注入规格 Δ：`R(S,τ)=(S′,Δ)`。
  - 被要求生成**与宿主技能上下文和预期功能兼容**的注入（而非插入固定 payload），保留无关内容，并精确记录修改。

- **VERIFIER（验证器，仅评估用）**：
  - 输入 S、S′、Δ、D、P，输出定位结果 L 与补丁移除结果 R：`V(S,S′,Δ,D,P)=(L,R)`。
  - **词汇相似度快速路由**：计算最大相似度 `r = max_{1≤i≤n} sim(norm(δ), norm(q_i))`，其中 `norm` 做小写化、空白折叠、去除 Markdown 格式符，`sim` 采用 Python `difflib.SequenceMatcher` 的 ratio（0~1）。**r ≥ 0.8** 直接判定为确认定位。
  - 其余有发现但未达阈值的情形交由**独立 LLM 裁判**裁定（输入：记录的注入、原版-注入版 diff、全部发现及证据与解释、补丁 P），判断是否有发现命中该注入、补丁是否移除/中和该行为。
  - L 映射为真阳性（至少一个发现命中记录注入）或假阴性；D=∅ 记为漏检，不计算相似度。
  - **验证本质上是静态的**：只能评估注入是否被识别、行为是否从补丁技能中移除，**不能保证全部合法功能被保留**。

### 2.2 实现与工程细节

- 基于 **LangGraph** 的智能体工作流编排。
- 支持三种配置：完整受控流水线、单独运行 BLUE PATCHER（单技能或技能集合）、分析外部受控实例（如 Skill-Inject，执行检测+修补+ground truth 评估）。
- 逐组件记录 LLM 调用次数、输入/输出/缓存 token 数与成本。
- 支持可配置 LLM provider；实验通过 **OpenRouter** 访问模型。
- 提供轻量 Web 界面浏览技能、发现、证据、补丁与评估结果。

### 2.3 威胁模型

- **攻击者模型**：可在技能被安装/更新前发布、修改或攻陷技能，控制技能包的任意组件（指令、元数据、脚本、配置、声明的依赖、外部资源引用），涵盖恶意作者、被攻陷的维护者/仓库账号、注册表与构建流程攻陷、依赖混淆、包篡改。
- **目标**：诱导智能体执行用户未授权的安全相关动作（数据外泄、任意代码执行等）。
- **假设**：技能已被选中并载入用于看似相关的请求，隔离"信任技能本身"带来的安全后果。
- **区分概念**：**注入攻击**（蓄意修改，如 Skill-Inject 与 RED INJECTOR 生成的实例）vs **潜在漏洞（latent vulnerabilities）**（技能中已存在的安全相关行为，如不安全处理不可信输入、过度权限、不安全依赖/下载、暴露的秘密或个人信息、可诱发未授权工具使用的指令）。
- **不建模**：安装后的利用、智能体框架或沙箱被攻陷、运行时沙箱逃逸、扫描后远程内容的突变。
