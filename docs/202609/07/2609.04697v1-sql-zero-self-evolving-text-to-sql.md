## 摘要
训练一个具有竞争力的Text-to-SQL智能体通常依赖于人工标注的自然语言/SQL对，这些标注成本高昂、具有领域特定性，并且是扩展到新数据库的瓶颈。我们表明，在零标注对的条件下训练一个具有竞争力的求解器是可能的。我们提出了SQL-Zero，一种提议者-求解器自博弈框架，其中挑战者和求解器从相同的基础LLM出发，唯一的真实标签就是针对数据库本身的执行结果。挑战者生成与求解器当前难度相匹配的SQL对（以“难但可解”为目标），并且两个角色通过GRPO交替更新，同时对挑战者施加模板级别的重复惩罚以防止多样性崩溃。在没有标签的BIRD数据库上进行训练，自博弈在BIRD开发集上相比零样本基线提升了6.6个百分点（3B规模）和7.3个百分点（7B规模）。它还在同一数据库上与在人类BIRD金标准上使用相同配方训练的匹配对照组相比得分更高，尽管精确配对检验未能证实这一差异。迁移效果取决于模型规模：在3B模型上，每一次迭代在未见过的Spider数据库和词汇扰动（Spider-Syn）下都优于基线，并且其性能下降程度也小于匹配的BIRD金标准对照组；而在7B模型上，只有第一次迭代保持了迁移效果。

## Abstract
Training a competitive Text-to-SQL agent usually depends on human-annotated natural-language/SQL pairs, which are expensive, domain-specific, and a bottleneck for scaling to new databases. We show it is possible to train a competitive solver with zero annotated pairs. We introduce SQL-Zero, a proposer-solver self-play in which a challenger and a solver start from the same base LLM and the only ground truth is execution against the database itself. The challenger generates SQL pairs calibrated to the solver's current difficulty (targeting "hard but solvable"), and both roles are updated with GRPO in alternating turns, with a template-level repetition penalty on the challenger to prevent diversity collapse. Training on BIRD databases with no labels, self-play improves over the zero-shot base on BIRD dev by 6.6 points at 3B and 7.3 points at 7B. It also scores higher than a matched control trained under the same recipe on human BIRD gold over the same databases, although an exact paired test does not resolve that margin. Transfer depends on scale: at 3B every iteration outperforms the base on unseen Spider databases and under lexical perturbation (Spider-Syn), where it also degrades less than the matched BIRD-gold control, whereas at 7B only the first iteration preserves transfer.

### 1. 核心问题与整体含义（研究动机与背景）
- **核心痛点**：传统Text-to-SQL系统的训练高度依赖人工标注的“自然语言问题/SQL查询”配对数据。这类标注成本高昂、依赖领域专家，且难以扩展到新数据库，成为规模化发展的核心瓶颈。
- **研究问题**：能否在**完全不使用任何人工标注NL-SQL训练对**的前提下，训练出一个具有竞争力的Text-to-SQL求解器？
- **整体含义**：该研究挑战了“无标注数据则无法有效训练”的既有假设，提出一种将执行结果作为唯一真值的自博弈训练框架，探索了一条低成本、可扩展的模型训练新路径，对数据库访问、数据分析和智能体训练领域具有潜在的重要意义。

### 2. 方法论：SQL-Zero 框架
- **核心思想**：提出“提出者-求解者”（Proposer-Solver）的自博弈（Self-Play）循环。从同一个基础LLM分别初始化一个**挑战者（Challenger）** 和一个**求解器（Solver）**，两者在迭代中互相促进、共同进化，整个过程仅由数据库执行结果提供反馈，无需任何人工标注。
- **训练流程（三步循环）**：
    1.  **训练挑战者**：挑战者以当前求解器为“难度标尺”，通过强化学习目标是生成“难但可解”（hard-but-solvable）的SQL任务对，并使其训练数据符合求解器的当前能力区间。
    2.  **生成与验证**：挑战者生成候选SQL-first任务对。系统仅接受能通过执行验证、结果非空且无SQL泄露的任务，并按SQL模板去重，以保证数据的质量和多样性。
    3.  **训练求解器**：求解器在挑战者生成并被验证过的任务对上通过GRPO算法进行强化学习，优化其生成正确SQL的能力。更新后的求解器反过来又成为下一轮挑战者训练的“难度考官”。
- **关键技术细节**：
    - **求解器的三层执行奖励（r_sol）**：仅依靠数据库执行结果。完全匹配奖励1.0，执行成功但不匹配奖励0.1（保留组内差异），执行失败奖励0.0。
    - **挑战者的综合奖励（r_ch）**：结合了格式正确性（f）、难度奖励（d，根据5次采样中成功次数的分布来计算）和模板级重复惩罚（ρ，用于防止生成任务单一化），并对各复杂度分层进行GRPO分组更新。
    - **其他配置**：在求解器奖励中加入了一个次要的“推理过程”（reasoning block）奖励项，保证训练过程稳定。

### 3. 实验设计
- **训练数据集**：使用 **BIRD** benchmark 的训练数据库子集（共64个数据库），进行无标签训练。
- **评估基准（Benchmark）**：
    - **领域内评估**：BIRD development（dev）集。
    - **迁移评估**：Spider test集（评估跨数据库泛化能力）和Spider-Syn集（评估对词汇扰动的鲁棒性）。
- **对比方法与基线**：
    - **SQL-Zero本身**：基于Qwen2.5-Coder-3B-Instruct和7B-Instruct模型，分别进行3次迭代训练。
    - **同规模基线**：预训练零样本模型（zero-shot base）。
    - **强监督基线**：
        - **Gold-BIRD-control**：使用与SQL-Zero相同3B配方但基于人工标注BIRD gold数据训练的控制组。
        - **CSC-SQL-3B**：一个更强大的基于gold数据训练的基准（使用原始评估协议）。

- **评估协议**：统一的OmniSQL evaluation pipeline（除专门的对照实验外），使用官方执行准确率（EX）作为评分标准。

### 6. 主要结论与发现
- **无标签领先零样本**：在该研究条件下，执行验证的自博弈显著优于同尺寸的零样本基础模型。最佳迭代下BIRD dev准确率在3B上提升6.6点，7B上提升7.3点。
- **无标签对比有标签**：与其配方相同的、使用人工BIRD gold数据训练的对照组相比，SQL-Zero的3个迭代在BIRD dev上均表现更好（超出1.8-3.4点），但统计检验（McNemar exact test）显示差异不显著。
- **迁移能力取决于规模**：3B模型在每一次迭代中都能稳定迁移到未见过的Spider数据库和Spider-Syn（词汇扰动）场景，甚至优于同配置的gold对照组。而7B模型仅第一次迭代保持了良好的迁移性能，后两次迭代过度拟合训练环境，导致迁移能力大幅下降。
- **难度控制与多样性是基石**：实验证明，若没有挑战者的难度控制和多样性惩罚，单纯的自博弈在7B模型上会导致性能崩溃。而有了正确的难度控制，模型才能稳步提升。
- **自博弈能补充强监督初始化**：在已有的强监督模型（OmniSQL-7B）上，额外进行一轮自博弈训练，仍能提升其在BIRD和Spider-Syn上的表现，并保持Spider test的迁移能力。

### 7. 优点
- **方法创新性强**：提出了一个清晰的、无监督的、执行验证的自进化闭环框架，跳出了对人工标注的依赖，具备较高实际应用潜力。
- **实验设计较为科学**：设置了一个“匹配的gold-control”对照实验，尽可能隔离了“标注”变量，使核心结论更具说服力。且使用了严格的配对统计检验，并坦诚地报告了统计不显著的结果。
- **消融实验相对完整**：详细探讨了主要组件（推理奖励、训练时间、重复惩罚、难度控制）的影响，并对一些初步发现进行了深入的诊断性分析。
- **评估透明度高**：在主结果图中，明确指出了不同评估协议（如统一提示词 vs 官方评估）之间的差异，并确保同一表格中的数值使用完全一致的协议，避免了比较上的混淆。

### 8. 不足与局限
- **模型和算法演变迅速，但研究本身存在天花板**：作为以自博弈为核心的训练方法，其迭代过程未能持续累积增益。最佳结果出现在第二轮（3B），且后续迭代在更广泛的基准上表现并未进一步大幅提升，说明其提出的自进化算法难以突破当前数据分布带来的瓶颈。
- **训练不稳定**：论文多次指出是单次运行，训练本身存在较高的不确定性和随机性，训练成功与否和性能表现高度依赖于一系列复杂的超参数和机制设计。
- **泛化范围的局限**：研究基于Qwen2.5-Coder系列和SQLite数据库，未测试跨模型家族、跨数据库方言（如PostgreSQL）的情况，限制了方法的通用性。
- **对比基准的局限**：与CSC-SQL-3B、OmniSQL等标杆系统相比缺乏公平性（例如CSC-SQL-3B使用了大量候选采样和修正模型），这导致无法通过对这些系统进行严格对照来判断自身方法的绝对领先程度，更多是展示可行性。
- **统计不显著的差距**：虽然无标签方法在数值上超过了同配方的有标签控制组，但精确配对检验无法在统计上确立这一优势，结论强度打了折扣。
