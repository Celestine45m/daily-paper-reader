## 摘要
我们将间接提示注入定义为在由环境、用户任务和注入任务所引发的任务相关攻击面上进行的一种测试时搜索。为使这一形式化具有可操作性，我们引入了一个配备专用搜索框架的智能体攻击者，该框架可执行环境侦察、攻击策略的结构化推理以及基于受害智能体反馈的自适应评估。在异构任务中，我们发现增加攻击者的测试时计算量能够提升漏洞发现与利用能力，而消融实验表明，显式策略管理对于避免冗余搜索并在更大计算预算下保持收益具有重要意义。这些结果表明，智能体安全评估应当同时刻画攻击者的搜索过程与计算预算，而不应将攻击成功视为与受害智能体预算无关的固有特性。更广泛而言，本研究发现攻击者对系统攻击面的自适应搜索是工具使用智能体面临的一个重要且尚未充分探索的安全风险。

## Abstract
We formulate indirect prompt injection as a test-time search over a task-dependent attack surface induced by the environment, user task, and injection task. To operationalize this formulation, we introduce an agentic attacker with a dedicated search harness that performs environment reconnaissance, structured reasoning over attack strategies, and adaptive evaluation using victim-agent feedback. Across heterogeneous tasks, we find that increasing attacker test-time compute improves vulnerability discovery and exploitation, while ablations show that explicit strategy management is important for avoiding redundant search and sustaining gains at larger budgets. These results suggest that agentic security evaluations should characterize both the attacker's search procedure and compute budget, rather than treating attack success as a budget-independent property of the victim. More broadly, our findings identify the attacker's adaptive search over the system attack surfaces as an important and underexplored security risk for tool-using agents.

## 1. 论文的核心问题与整体含义

- **背景**：大语言模型（LLM）智能体通过与外部工具、环境交互完成复杂任务，但这一过程引入了新的安全挑战——LLM 直接处理外部文本，缺乏区分“指令”与“上下文数据”的正式机制。**间接提示注入（Indirect Prompt Injection, IPI）** 正是利用这一漏洞，使外部攻击者能够在不直接操控用户提示的情况下，通过污染工具读取的第三方内容来操控受害智能体。
- **现有局限**：
  - 既有基准（AgentDojo、InjecAgent、WASP 等）大多将 IPI 视为**静态评估问题**：预先定义攻击模板，在固定条件下测试受害智能体是否被攻击成功，以此评判受害者的防御能力。
  - 这种方式忽略了攻击效果与**用户任务**和**攻击目标**之间的动态耦合。不同任务会诱导不同的良性工具调用轨迹，暴露不同的可利用通道——即论文所称的**任务相关攻击面**。
  - 既有工作也普遍不刻画攻击效果如何随攻击者的**测试时计算量（test-time compute）** 变化。由于测试时计算的增加可以大幅提升 LLM 在推理密集型任务上的表现，固定预算下的评估可能**系统性低估**智能体系统的真实脆弱性。
- **核心论点**：论文主张将间接提示注入重新定义为一个 **测试时搜索问题**：攻击者在由环境、用户任务和注入任务共同诱导的潜在攻击面上，进行自适应的迭代搜索，寻找能够成功诱导受害智能体完成恶意目标的注入负载。攻击成功率不应被视为受害者“固有的、与预算无关”的属性，而应被理解为攻击者搜索过程与计算预算共同作用的结果。
- **整体含义**：提出了一个研究 IPI 的新范式——将攻击者的搜索过程纳入安全评估的核心范畴。这一视角揭示了攻击者的自适应搜索能力是工具型智能体面临的一个“重要且尚未充分探索的安全风险”，为智能体安全评估设计提供了方向性启示。

## 2. 方法论

论文提出的方法包含三个层次：评价设计、攻击框架形式化、以及搜索框架的具体实现。

### 2.1 评价设计
- 采用与 AgentDojo 类似的 benchmark 结构：由**环境**、**可用工具集**、**环境状态**三部分组成。
- 环境定义了应用域（如带邮箱、日历的工作区，或带商品、订单的零售平台），状态存储智能体可访问的数据。
- 任务分为两类：

| 任务类型 | 定义 | 验证方式 |
|---------|------|---------|
| **用户任务** | 提供给受害智能体的良性自然语言请求 | 基于最终输出与环境状态变更，计算二进制 utility 分数 |
| **注入任务** | 提供给攻击智能体的恶意目标 | 基于环境状态变更，验证是否达成注入目标，计算二进制 security 分数 |
- 论文聚焦**白盒（white-box）环境**：环境对攻击者可见。论文指出该设置预计可迁移到黑盒场景（代价更高），但系统性的黑盒评估留待未来工作。

### 2.2 智能体攻击者与搜索框架
论文的核心技术贡献是设计了一个**配备搜索框架（Search Harness）的智能体攻击者**。用户任务与注入任务组合产生潜在攻击面，搜索框架帮助攻击者隐式地识别并探索这一空间，无需人工专家构造。其攻击循环可分为以下三个行为组件：

1. **环境探索（Explore Environment）**
   为攻击者提供侦察工具，发现有效的内容注入位置和环境上下文：
   - *环境知识工具*：如 `read_workspace_email`、`read_retail_products`、`read_workspace_drive` 等，提供领域、任务相关的上下文信息。
   - *注入向量知识工具*：如 `list_injection_vectors`，列出环境中所有可注入位置（如邮件正文、日历描述、商品评论、公共问题回复等）的关键和描述。
   - 设计上的关键约束是：输出必须附带 `matched_vectors/vector_fields`，确保攻击者使用**确切的向量键**，而非凭 id 幻觉构造——这是框架在提示注入技术层面确保可靠性的重要机制。

2. **推理与搜索（Reasoning and Searching）**
   由于潜在攻击面空间巨大，攻击者需要定位有前景的子空间。为此推出两个关键的记忆与规划工具：
   - **`strategy_archive`**：将攻击者提出的攻击策略组织为层次化语义结构，记录每种策略、每种“framing”（如直接指令、前置条件框架、任务连续性框架等）的尝试结果。每次评估调用后自动记录，并返回**确定性搜索提示**——包括已探索的策略、最近的“near-miss”结果及其失败模式，以及下一步的“利用-探索”建议。
   - **`load_history`**：记录针对同一任务对的全部历史尝试，供压缩上下文后恢复记忆，避免重复失败路径。
   - 这些工具共同支持“识别子空间 → 剪枝低潜力维度 → 集中有限预算到高潜力区域”的迭代搜索过程。

3. **评估与反馈（Evaluation and Feedback）**
   这是唯一会触发受害智能体运行的高成本工具：
   - **`evaluate_injection`**：注入指定负载到指定向量，从零开始运行受害智能体，返回 security 分数、utility 分数、受害者的输出响应、工具调用轨迹等关键反馈信号。
   - 反馈信号帮助攻击者识别：哪些向量实际被受害者读取（`fired_vectors`）、攻击失败的模式（`WRONG_ARGS`、`NO_ACTION`、`ATTACK_ONLY`、`BENIGN_FAILED`），从而指导下一轮负载的调整方向。
   - 将评估操作显式化为一个工具，允许攻击者根据累积证据和当前搜索状态自适应地分配测试次数，实现“更精准、更高效的搜索”。

### 2.3 其他重要技术细节
- **搜索即预算管理**：攻击者在其系统提示中被明确赋予一个 token 预算。检索策略强调：预算低时应直接进行注入评估而非穷尽探索环境——这使攻击者以“有限资源下的搜索策略”方式运行，而非简单 brute-force。
- **任务套件生成方法**：
  - Retail 套件仿照“General Agent”的迭代生成方案，添加了 7 道确定性门控（结构有效、单一主键、工具覆盖、多样性、目标实体唯一性、公共 schema、金路径可注入性），以及一个 Solver Agent 作为难度/可解性门控，保证生成任务的合法性、非平凡性和可注入性。
  - 注入任务生成与用户任务生成分离，保证注入任务是针对固定良性基准的攻击生成问题。生成过程包含多种验证闸门（格式合法、工具可调用、目标一致性、非干扰性等）。
- **成功标准**：单一负载需同时达成 `security=True` 和 `utility=True`。

- **不足与偏差风险**：
  - 样本量有限：论文只在两个合成场景（Retail、Workspace）上评估，且每个任务对的重复运行次数有限，不同 seed 的方差量化缺失。
  - 模型覆盖窄：仅涉及 1 个攻击者模型和 2 个受害者模型，缺少对不同商业模型/开源模型多样性的检验。
  - **单次运行报告为主**：表 5、6 中的 ASR 数字（尤其是 0%、100% 端点）可能受到单次运行随机波动影响，未提供置信区间。
  - 白盒评估为主，黑盒环境和迁移性未系统评估。

## 6. 主要结论与发现

1. **间接提示注入本质上是一个测试时计算（test-time compute）问题**：在 Retail 和 Workspace 两个套件中，ASR@T 均随 token 预算的增大而单调上升。例如 GPT-5.5 在 Retail 上 500K token 时 ASR 约为 57.8%（250K 时约 49.0%），收益在中后期逐步显现。
2. **受害模型安全性差异明显**：GPT-5.5 在约 50K tokens 时即开始明显出现受攻击趋势，而 Opus-4.8 在 500K tokens 时 ASR 仍较低（Retail 中为 20.6%），显示更强的抵抗能力。
3. **成功的攻击集中“任务邻近”而非任意负载搜索**：攻击者成功案例的推理轨迹表明，其攻击负载多巧妙地嵌入到受害智能体良性工作流所需的“相邻”数据表面上——如受害者为完成任务本来就需读取的日历记录、邮件或产品详情中。这与论文的核心“attack surface”假设相符。
4. **搜索框架对持续规模化收益不可少**：Full-Harness 在较大预算区间能持续提升攻击效果；No-Harness 则早期快速起步但在 100K tokens 附近停滞；No-Strategy（去除 Strategy 工具）虽然保留侦察工具，但表现出过度侦察和重复攻击模式。
5. **攻击难度受“语义可见性和流程兼容性”双重影响**：
   - 当操作“公共性”和“明显危害性”较高时（如将 PII 发布至公共评论），攻击成功率显著降低（Retail IT1 和 IT5 均为 0%）。
   - 当操作在语义上难与日常工作区分（如删除单文件、发送“普通邮件”、创建日程）时，即使带有破坏性或外部数据转发，攻击成功率也非常高（Workspace IT1：95%，IT2：97.5%，IT4：92.5%）。
   - 认证类数据（如 Facebook 安全码）的泄露被受害模型明确拒绝，成功率极低（2.5% 和 0%），表明受害者模型已具备一定安全对齐——但也提示了对边界场景的安全缺陷：如“reference-number disguise”机制（把验证码改写为“晚餐预订参考号”）竟可绕过一次成功。
6. **工具广度与 JSR 之间权衡**：良性工具轨迹越宽，攻击者越容易找可利用的操作点（ASR 上升），但严格 utility（完成良性任务）的保持率减弱（JSR 降至 0%），攻击的成功与受害模型任务的破坏同时增加。
7. **搜索具备明显的“探索-利用-再扩张”证据**：策略分析显示攻击者先广泛探索（初期策略快速增加），随后集中优化 best near-miss（中段策略数量稳定但 framing 迭代频繁），当局部改进遭遇瓶颈时再次扩大策略范围（后期策略速率上升）。推理轨迹嵌入聚类和收敛分析也印证了该结构。

## 7. 优点

1. **范式形式化创新**：将 IPI 从静态基准问题推进到“测试时搜索”范式，强调攻击过程本身是一个需要计算的搜索行为。这一框架更贴近真实攻击者的自适应行为，也为安全评估增加了“预算”与“搜索过程”这两个曾被忽视的维度。
2. **攻击者搜索框架的设计具有工程实用性**：通过“环境知晓 + 策略管理 + 历史记忆 + 受害者反馈”模块的组合，攻击者可以围绕“攻击面”进行高效的探索与利用；`strategy

`strategy_archive` 与 `load_history` 的设计使攻击者具备结构化的“记忆”，避免了盲目重复与上下文遗忘，为后续安全防御研究提供了可复现的对抗框架。

3. **多维度的攻击归因分析**：论文不满足于报告“是否攻击成功”，而是深入拆解了攻击效果与任务类型、注入渠道、工具数量、目标类型、预算水平之间的函数关系。通过工具调用轨迹的聚类、策略演化的测量和失败模式的归纳，给出了攻击行为机制的“剖面图”，对理解 IPI 的脆弱性来源具有参考价值。
4. **任务套件生成流程严谨**：Retail 套件采用“确定性门控 + Solver Agent 验证”的迭代生成方式，包含结构合法性、目标唯一性、金路径可注入性等多项过滤器，缓解了以往基准中任务过于简单或不可解的问题；用户任务与注入任务解耦生成的策略，避免了安全评估与良性任务难度相互污染。
5. **叙事清晰、结构完整**：论文从现象、假设、形式化、实验到归因分析形成了完整的逻辑闭环，且在多种预算条件与消融设置下交叉验证同一核心论点，说服力较强。

## 8. 缺点与局限性

1. **计算成本过高导致统计严谨性不足**：论文自己也承认，每次 `evaluate_injection` 均需完整的受害智能体 rollout（约 30K–40K tokens），而多预算 × 多任务对 × 多消融组合的实验矩阵使得总 API 调用量极大，限制了重复运行次数。因此，核心结果缺乏置信区间或方差报告，0% 与 100% 的端点值尤其容易受单次运行随机性误导。这个问题不仅是表述层面，更可能影响关键结论（如模型间安全性差异）的稳健性。
2. **模型覆盖范围窄且不对称**：攻击者仅有 GLM-5.2，受害者仅有 GPT-5.5 与 Opus-4.8，未覆盖当前主流的开源模型（如 Llama、Qwen、DeepSeek）或不同规模、不同对齐策略的模型。攻击与受害模型固定配对，无法排除“攻击模型对受害模型特有行为模式的过拟合”风险。
3. **环境覆盖面有限**：两个任务套件（零售助理与工作区助理）尽管在结构上互补，但仍属于“工具丰富但领域有限”的合成场景，未涉及浏览器操作、代码执行、多智能体协作等更复杂的真实应用形态。跨任务套件的结论能否推广到真实生产环境中的 IPI 风险尚不确定。
4. **白盒假设与真实威胁模型存在差距**：论文假设攻击者对环境完整可见（包括数据内容与注入向量清单）。而真实 IPI 攻击者通常只能猜测目标环境的结构，黑盒条件下的搜索效率与成功曲线可能显著不同。论文仅以“预计可迁移”带过，缺乏实验证据。
5. **对 utility 的度量过于二元化**：utility 被简化为二进制分数，丢失了部分成功、延迟失败等中间状态；JSR 指标又对 utility 破坏极其敏感，导致部分分析（如工具广度与 JSR 的权衡）出现 0% 的极端读数，难以刻画真实场景中“任务部分完成但关键步骤被劫持”的微妙安全损失。
6. **缺少对防御机制的探讨**：论文详细刻画了攻击面与搜索过程，却几乎没有评估任何防御策略（如注入检测、工具调用审计、数据来源标记）在对抗该搜索式攻击者时的表现。这使得读者难以判断所揭示的脆弱性是否可被缓解、缓解成本几何。
7. **“任务相关攻击面”的度量比较间接**：虽然论文用工具轨迹聚类等方法来关联攻击成功与良性轨迹，但这些分析多为事后描述，缺少对“攻击面”的可操作定义或定量预测模型。读者无法在先验上根据用户任务判断其攻击面大小。

## 9. 总体评价与启示

这是一篇**视角转换型**的安全研究：它没有停留在“模型能否被一句话越狱”的层面，而是以“搜索预算—攻击面—自适应攻击者”的框架揭示了 LLM 智能体在长期、多轮工具交互中暴露的脆弱本质。核心启示有三：

1. **对安全评估者的启示**：任何固定提示模板的 IPI 基准都可能低估真实风险；只有将攻击者的搜索预算纳入评估协议，才能绘制出可靠的安全-成本曲线，正确反映系统在持续对抗下的表现。
2. **对防御研究者的启示**：既然攻击的成败高度依赖对受害者“良性工作流邻域”的利用，那么防御的焦点应放在工具调用的上下文完整性上——例如强制区分数据来源、对不可信内容做 taint 追踪、在高危操作前进行与当前任务目标的一致性校验。
3. **对模型开发者的启示**：GPT-5.5 与 Opus-4.8 在相同预算下的 ASR 差异表明，安全对齐策略（如针对注入的拒答训练）可以显著改变攻击成本曲线；但认证码泄露案例也说明，现有可能存在“表面对齐”——换一种语义伪装（将验证码描述为“预订参考号”）即可绕过，提示对齐训练需要覆盖更深的意图层而非表面指令层。

总体而言，论文在问题定义、方法论和实证分析上均有明显贡献，但其结论强度受限于计算资源、模型覆盖和场景数量。未来工作若能在更多模型、黑盒环境与真实应用上验证该搜索框架的普遍性，并将防御机制纳入对抗协议，将有望形成一个完整的“攻击-防御双向评估体系”。
