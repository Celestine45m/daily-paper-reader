## 摘要
计算机使用代理（CUA）是一种视觉-语言模型，能够感知屏幕并通过鼠标、键盘和终端在真实操作系统上操作，它们正越来越多地被部署用于自动化日常数字任务。由于它们在运行过程中可能接触到不受信任的内容，因此容易受到间接提示注入（IPI）攻击，在这种攻击中，对手会在代理将要读取的内容中植入指令，并将其重定向到违反用户意图的行为。现有的CUA安全基准评估的是手工编写的固定注入，这可能低估了自适应对手所带来的风险。我们提出了SIR，一种黑盒IPI攻击方法，它（i）从一小库用简单语言陈述的可复用原则中组合出隐蔽的注入，并且（ii）将组合过程包裹在一个迭代反馈循环中，该循环诊断受害者失败的轨迹，并将绕过方法提炼为新的命名策略，这些策略可跨任务重新应用。与先前针对网络代理的红队测试不同，我们针对操作系统层面的CUA，并使用完全确定性的预言机来评分攻击，通过检查文件系统、服务和权限状态而非LLM评判器来评分。在实验中，我们评估了三个前沿CUA。结合反馈的原则组合将攻击成功率提高到超过手工编写的基线，例如在Claude Opus 4.8上从4%提高到24%，在Gemini 3.5 Flash上从0%提高到28%，同时良性任务仍然完成。针对一个模型发现的原则进一步迁移到不同架构，且无需额外反馈。

## Abstract
Computer use agents (CUAs) are vision-language models that perceive a screen and act on a real operating system through mouse, keyboard, and terminal, and they are increasingly deployed to automate everyday digital tasks. Because they can be exposed to untrusted content while operating, they are vulnerable to indirect prompt injection (IPI), in which an adversary plants instructions in content the agent will read and redirects it toward actions that violate the user's intent. Existing CUA safety benchmarks evaluate fixed injections written by hand, which may underestimate the risk posed by an adaptive adversary. We present SIR, a black box IPI attack that (i) composes stealthy injections from a small library of reusable principles stated in plain language and (ii) wraps composition in an iterative feedback loop that diagnoses the victim's failed trajectories and distills the bypasses into new, named strategies that are reapplied across tasks. Unlike prior red teaming of web agents, we target CUAs at the operating system level and score attacks with a fully deterministic oracle, using checks on filesystem, service, and permission state rather than an LLM judge. On experiment, we evaluate three frontier CUAs. Composing principles with feedback raises the attack success rate over a baseline written by hand, for example from 4% to 24% on Claude Opus 4.8 and from 0% to 28% on Gemini 3.5 Flash, while the benign task still completes. Principles discovered against one model further transfer to a different architecture with no additional feedback.

  - 对手可以观察代理的响应、诊断攻击失败的原因、迭代调整攻击方法。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想

- **反常规思路**：现有自改进攻击者从**成功**中学习（挖掘成功越狱的策略或库），而 **SIR 从失败中学习**——当 CUA 拒绝注入时，其拒绝行为揭示了背后的防御机制，SIR 将该拒绝作为监督信号，诊断防御机制，并将绕过方法蒸馏为可复用的、自然语言表述的攻击原则。
- **以原则组合为核心**：从一个小的可复用基础原则库出发，用攻击者 LLM 为每个任务组合定制隐蔽注入；迭代反馈循环将失败轨迹中的防御模式蒸馏为新的命名策略，加入原则库，实现跨任务和跨模型迁移。

### 2.2 系统架构：两个嵌套循环

- **内循环——组合式攻击搜索（Compositional Attack Search）**：
  - 维护基础原则库 P_base = {P1, …, Pn}，覆盖内容级策略（如前置条件框架 P1、权威嵌入 P2、错误恢复 P3、副作用掩蔽 P4、多步稀释 P5、技术术语 P6、跨通道重定向 P7）和传递级策略（如视觉混入 D1、高信任位置 D2、轨迹感知时机 D3、平台最优通道 D4）。
  - 对每个任务通过三个依次进行的攻击者 LLM 调用生成注入：
    1. **Seed**：给定良性指令 b_i 与敌对目标 g_i，提出初始攻击思路；
    2. **Compose**：从原则库选择任务相关的原则子集 C_i ⊆ P_base（通常 2–4 个），改写初始方案使其同时运用所选原则；
    3. **Refine**：去除明显的攻击性措辞，融入反馈循环发现的新策略 S^(r)（两个循环在此连接）。
- **外循环——失败驱动的策略发现（Failure-Driven Strategy Discovery）**：
  - 收集所有未能达成敌对目标的攻击轨迹（失败轨迹），交给分析器 LLM 执行两步操作：
    1. **Diagnose（诊断）**：批量检查失败轨迹，识别反复出现的失败模式（如来源不信任、目标敏感性、因果不自然、命令式语言检测等），对应 CUA 的具体防御行为；
    2. **Distill（蒸馏）**：为每种模式生成候选策略，包含名称、失败诊断、绕过机制、组合指导和具体示例；将 Top-K 个非冗余策略合并进共享原则库，后续全部任务均可用。
  - 循环反复直到任务首次攻击成功或达到轮数预算 R。

### 2.3 问题形式化与威胁模型

- 形式化目标：
  z*_i ∈ arg max_z Pr[ O^adv_i(h_i(z)) = 1 ∧ O^ben_i(h_i(z)) = 1 ]
  （攻击成功 = 敌对目标与良性任务需**同时完成**，防止“严重破坏却断送用户任务”的攻击。）
- 攻击者能力受限：只控制一块不受信内容区域（如论坛帖子），不可改变用户指令、操作系统或区域外内容；运行中不干预；严格黑盒，无法访问权重、梯度、token 概率或系统提示；只能观察外部可见的行为（屏幕状态轨迹、推理痕迹、执行动作）以及每轮评估结果。
- **确定性评估**：用编程式预言机（检查文件系统、服务状态、权限状态）而非 LLM 评判器来判断攻击是否成功。

### 2.4 关键创新点

- 将“组合原则”范式（CoP）从单轮越狱扩展到环境内嵌的 IPI 攻击；
- 将失败的防御行为本身转化为攻击原则（从“防御”中学习）；
- 原则以自然语言统一表示（基础原则与发现策略仅在来源上不同），策略库完全通过提示级自然语言维护，无需微调。

## 6. 主要结论与发现

1. **SIR 显著提升攻击成功率**：在三个目标模型上，SIR 将 ASR 从固定注入基线大幅提高：
   - Claude Opus 4.6：16% → 54%（基线 → SIR）
   - Claude Opus 4.8：4% → 24%
   - Gemini 3.5 Flash：0% → 28%
2. **静态基准严重高估模型鲁棒性**：基线注入在模型升级时急剧退化（16% → 4% → 0%），若只依据静态基准，会得出 Gemini 3.5 Flash 几乎免疫 Web→OS 注入的结论；但 SIR 在对抗性最强的模型上仍达到 28% 的成功率——自适应攻击揭示了固定基准无法暴露的真实攻击面。
3. **两个组件均有贡献**：
   - 组合式搜索的增益（Δcomp）：6%–18%，绕过了表面防御（如紧迫模式检测、权威声明过滤）；
   - 反馈驱动的发现增益（Δfb）：12%–20%，策略表达了基础原则无法覆盖的防御绕过；在 Gemini 3.5 Flash 上增益最大（8% → 28%）。
4. **发现的策略可跨架构迁移**：在 Opus 4.6 上蒸馏出的 P9（错误佐证）与 P10（条件延迟执行），不经过任何额外反馈即可提升其他两个模型的 ASR（Opus 4.8：10% → 16%/14%；Gemini：8% → 18%/12%），说明反馈发现的是共享的攻击策略空间而非过拟合特定模型的载荷。
5. **不同模型暴露不同的防御弱点**：同一原则库在各模型上产生不同的组合分布（如 Gemini 更依赖副作用掩蔽 P4；Claude 更多配对前置条件框架 P1 与权威嵌入 P2 等），反映异构防御机制。
6. **各类任务难度梯度稳定**：数据外泄在所有模型上均最难（20%/10%/10%）；文件删除与篡改相对容易被伪装为常规维护；权限更改在 Opus 4.6 → 4.8 间出现显著下降（50% → 0%），表明新模型加强了对权限修改操作的审查。

## 7. 优点

- **方法设计亮点**：
  - **从失败中学习**：将代理的防御行为本身作为攻击策略的“导师”，区别于现有方法只从成功中学习的范式，方法论上具有原创性。
  - **原则组合 + 反馈蒸馏**：攻击在“人类可读策略空间”中搜索，策略可在不同任务、不同模型间迁移复用，具有可解释性和可转移性。
  - **确定性执行状态评估**：全部使用不可被 LLM 评判器操纵的文件系统/服务/权限状态检查，排除了评判器偏置问题。
  - **联合成功标准**：攻击只有同时完成敌对目标与良性任务才算成功，严谨而合理。
  - **严格黑盒设置**：攻击者不访问模型权重/梯度/概率，贴近真实威胁场景。
  - **跨模型迁移验证**：用实验证据证明发现的策略具有泛化性，而不仅是单个模型的过拟合载荷。
- **实验验证亮点**：
  - 消融清晰分离了组合搜索与反馈发现各自的贡献；
  - 跨模型迁移实验设计合理（冻结原则、不加反馈），有说服力；
  - 分类别报告攻击成功率，揭示攻击难度梯度；
  - 提供了成本估算、完整原则库、提示结构和实现细节，便于复现与后续研究。

## 8. 不足与局限

- **可复现性与时效性**：受害者 CUA 为专有 API 模型，随时间迭代，结果是特定时间点的快照，后续模型版本可能无法复现相同结论。
- **成本高昂**：每轮反馈约 $150–$250（Claude 模型），限制了可开展的轮数、种子、基准数量，也限制了外部复现的可行性。
- **类别样本量不平衡**：七类攻击目标中部分类别（服务中断 n=4、工件植入 n=2、资源消耗 n=4）样本量过小，单独解释能力有限；整体任务量（50 个）对强结论而言仍属中等规模。
- **双用途风险**：SIR 产生可直接用于真实系统的可迁移攻击策略，若被误用可能对实际部署的 CUA 造成破坏；作者明确仅建议在负责任披露的沙箱环境中使用。
- **未覆盖更多模型与基准**：仅评估三个专有 CUA（Claude 和 Gemini 家族），未覆盖开源模型或其他厂商；仅基于 RedTeamCUA 一个基准；未测试防御侧（如如何设计更好的防御措施）。
- **原则质量依赖分析器**：策略蒸馏依赖 Grok-4.3 的诊断能力，分析器的选择对发现策略的质量与多样性有直接影响，但未作敏感度分析。
- **环境错误利用的特定性**：实验中利用了虚拟机上 Node.js 版本固定的可预测报错（fs/promises 缺失），这在真实场景中的可预测性可能不同，影响“错误佐证”等策略的普适性。
