## 摘要
大语言模型智能体将外部技能的输出置于其执行上下文中，从而使攻击者控制的数据能够影响后续的特权操作。现有防御措施主要对不可信内容进行分类或对提议的操作进行授权，但它们并未直接解决一旦不可信数据进入智能体状态，其未来权限应如何变化的问题。我们提出了SkillGuard，这是一种框架级执行强制层，它将此类事件视为污染，并限制未来能力，以切断所得状态与部署者定义的禁止状态之间的联系。在给定可靠的技能摘要和策略的情况下，SkillGuard使用技能影响图表示安全相关的转换，通过可转向性签名指定对技能参数的允许控制，并通过内联引用监视器调解调用。在污染发生后，它使用二进制、分数或分数流策略计算加权能力限制，无需辅助语言模型推理。我们在四个AgentDojo套件上评估了SkillGuard，使用两个后端LLM——Gemini 2.5 Flash和Llama3.3-70B——并与仅使用LLM的“无防御”基线以及三个不同系统层的防御方法（Spotlighting、CaMeL和AttriGuard）进行对比。我们构建了一个组合式攻击基准，其中每次攻击组合了单独不足以触发目标违规的观察结果，并在此基础上评估相同基线。在AgentDojo的工具知识攻击下，SkillGuard在两个后端上消除了四个套件中三个的攻击成功，并将Slack上的攻击成功率降至4.8%和14.3%。对于组合式攻击，它在Llama上优于所有基线，并在Gemini上以更高的良性效用匹敌最强基线。在相同攻击成功率下，分数流限制比二进制限制保留了更多能力。在两种设置中，SkillGuard均未增加模型调用或token开销。

## Abstract
Large language model agents place outputs from external skills into their execution context, allowing attacker-controlled data to influence later privileged actions. Existing defenses mainly classify untrusted content or authorize proposed operations. They do not directly address how an agent's future authority should change once untrusted data enters its state. We present SkillGuard, a harness-level enforcement layer that treats this event as contamination and restricts future capabilities to disconnect the resulting state from deployer-defined forbidden states. Given sound skill summaries and policies, SkillGuard represents security-relevant transitions with a Skill Impact Graph, specifies admissible control over skill parameters via steerability signatures, and mediates invocations with an inline reference monitor. Following contamination, it computes weighted capability restrictions using binary, fractional, or fractional-flow strategies without auxiliary language-model inference. We evaluate SkillGuard on four AgentDojo suites with two backend LLMs, Gemini 2.5 Flash and Llama3.3-70B, against an LLM-only No Defense baseline and three defenses at different system layers: Spotlighting, CaMeL, and AttriGuard. We construct a compositional attack benchmark in which each attack combines observations individually insufficient to induce target violation and evaluate the same baselines on it. Under AgentDojo's Tool Knowledge attacks, SkillGuard eliminates attack success on three of four suites for both backends and reduces it to 4.8% and 14.3% on Slack. Against compositional attacks, it outperforms every baseline on Llama and matches the strongest baseline on Gemini at higher benign utility. Fractional-flow restriction preserves substantially more capabilities than binary restriction at the same attack success rate. Across both settings, SkillGuard adds no model calls or token overhead.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体通过调用外部工具/技能（如搜索、数据库、代码执行、应用 API）来执行任务，技能输出会作为观察结果被加入到模型上下文中，并影响后续动作。
- **核心安全问题**：技能输出来自可信边界之外，攻击者可经由间接提示注入（Indirect Prompt Injection, IPI）在不可信内容中嵌入恶意指令，利用智能体的特权能力执行未经授权的操作，形成"困惑的副手"（confused deputy）问题。
- **现有防御的不足**：
  - 现有方法多分为两类：模型级防御（提示词隔离、检测器、训练对齐）和系统级防御（如 CaMeL、AgentArmor、AttriGuard），其主要关注点是"某个提议操作是否被用户请求所授权"，即每动作授权问题。
  - 它们没有回答一个关键问题：**一旦不可信数据进入智能体执行状态，智能体未来的权限应如何自动收窄**，以确保任何允许的后续执行路径都不会到达部署者定义的禁止状态。
- **本文目标**：将间接提示注入下的安全防御重新定义为**基于可达性（reachability）的能力约束问题**——通过切断污染状态到禁止状态的路径来实现安全，而非依赖对不可信内容语义的理解。

## 2. 方法论

### 2.1 核心思想
- SkillGuard 是位于可信执行框架（harness）内的强制层，采用"能力安全模型"（capability-based security model）。
- 当不可信技能输出进入智能体执行状态时，SkillGuard 将其视为**状态污染事件**，并触发能力限制计算，使得从当前污染状态出发，在受限后的技能影响图（SIG）上不再有任何可达路径通向部署者定义的禁止状态集 B。
- 安全决策不依赖 LLM 推理，而是基于显式图模型和组合优化，保证可解释性。

### 2.2 Skill Impact Graph（SIG）
- SIG 定义为带标签的迁移系统 \(G = (Q, \Sigma, \delta, q_0)\)，其中：
  - Q：安全相关状态集合；
  - Σ：注册技能集合；
  - δ：技能执行引起的状态迁移；
  - q0：初始状态。
- 每个执行事件 \(e=(\sigma, p, o)\) 会引起状态迁移，SIG 仅维护与安全相关的信息，不包含完整对话上下文。

### 2.3 Steerability Signatures（可操纵性签名）
- 每个技能参数被赋予一个类型与**可操纵性包络**（steerability envelope），限制可允许的参数值范围。
- 包络有三种精度：
  - **Exact**：类型或有限集合精确限定；
  - **Harness-enforced refinement**：由框架在调用边界强制执行的谓词（如文件路径限制在 `/home/user/reports/*`）；
  - **Conservative**：当无法可靠限定时设置为 \(⊤\)（完全放开）。
- 签名需要满足 \(A_i \subseteq E_i \subseteq \tau_i\)，即敌方可诱导值的集合必须包含在包络内。

### 2.4 Inline Reference Monitor（IRM）
- IRM 位于 LLM 与技能执行之间，属于抑制自动机（suppression automaton）。
- **预检**：技能是否在当前能力集中；每个参数是否满足当前可操纵性签名。
- **执行后检查**：验证输出是否合法，不合法则丢弃，不更新执行状态。
- IRM 只通过/拒绝操作，不终止智能体，也不插入合成动作。

### 2.5 能力限制机制（Capability Restriction）
- 当污染状态更新后，SkillGuard 解决一个加权限制问题，目标是：\(W(R,T)\) 最小化，且 \(Reach_{G(R,T)}(q) \cap B = \emptyset\)。
- 三种策略：
  - **Binary（二值）**：引入 0/1 决策变量，删除整个技能（能力），路径约束要求每条从 q 到 B 的路径至少有一个被移除能力的边。
  - **Fractional（分数）**：对选中删除的能力，用连续变量 \(y_c \in [0,1]\) 表示收紧程度，通过收紧参数包络而非完全删除能力来切断路径。
  - **Fractional-Flow（分数流）**：在整个 SIG 上联合优化能力选择与收紧程度，使用最小费用流/最小割，考虑多路径共享，避免不必要的能力删除。
- 复杂度分析：构建网络后使用 Dinic 算法求解，复杂度为 \(O((n+m)^2(kn+m))\)，其中 n 为技能数，m 为图迁移数。

### 2.6 安全性质
- 形式化定义了四个安全性质：
  - State Safety（SS）：不进入禁止状态；
  - Context Integrity（CI）：安全敏感参数不被未授权来源影响；
  - Capability Non-Escalation（CNE）：能力集只减不增；
  - Information Flow Confidentiality（IFC）：敏感信息不流向未授权技能。
- 通过归纳法给出了安全性质保持的证明（命题 1）。

## 6. 主要结论与发现

- **单步 Tool Knowledge 攻击**：
  - SkillGuard 在 Travel、Banking、Workspace 上实现双模型 0% ASR，在 Slack 上分别降至 4.8%（Gemini）和 14.3%（Llama）。
  - 优于 CaMeL、AttriGuard、Spotlighting 与 No Defense。
- **组合式攻击**：
  - Llama 上取得最低 ASR（8.00%）和最高 UA（81.82%）；
  - Gemini 上 ASR 为 14.29%，与 CaMeL 的 14.00% 几乎持平，但 BU 高出 10 个百分点（92.27% vs 82.27%）。
- **能力保留**：
  - Fractional-flow 在 Travel 上保留 93.21–94.08% 能力，Binary 只保留 76.25–79.29%，而 ASR 均为 0%。
- **开销**：
  - SkillGuard 保护过程零额外 LLM 调用、零额外 token；
  - 端到端延迟远低于 CaMeL 与 AttriGuard（例如 Llama-Travel 从 CaMeL 的 147.40 s 降至 34.57 s）。
- **残余攻击失败原因**：
  - Slack 上的残余攻击或因攻击目标在 SkillGuard 模型中只属于"污染事件"而非禁止状态，或因攻击动作在污染限制生效前已完成。
  - 组合攻击的失败点在于：可操纵性包络可能允许未见参数、单一包络无法捕捉跨多次调用的组合目标。

## 7. 优点

1. **问题重塑新颖**：将间接提示注入防御从"逐动作授权"提升到"污染后可达性约束"，在概念上更加直接。
2. **不依赖语义理解**：不判断内容是否恶意，而是保守标记为污染，避免了 LLM 对内容识别的不可靠性。
3. **无额外模型推理**：仅需轻量图分析和最小割计算，保护开销低，且安全逻辑可解释。
4. **细粒度能力约束**：通过分数/分数流策略实现了在相同安全水平下显著更高的能力保留，避免了粗粒度删除带来的功能损失。
5. **完善的实验体系**：覆盖多种攻击类型、多套件、多模型，并构建了组合式攻击基准，提供了充分消融和敏感性分析。
6. **安全性质可证明**：形式化定义了四个安全要求并给出归纳证明，提供了可验证的安全保证。
7. **组合式攻击基准的构建过程严谨**：通过消融验证确保每个攻击都真正依赖多步骤组合，而非单个碎片即可触发。

## 8. 不足与局限

1. **依赖策略与摘要的正确性**：安全保证建立在技能摘要、可操纵性签名和部署策略正确的前提上；若策略不完备或签名不准确，可能出现绕过（论文的自适应攻击已展示）。
2. **残余攻击场景未完全解决**：Slack 上仍有 ASR > 0（4.8% / 14.3%），原因是部分攻击目标不在 SkillGuard 的禁止状态集合内，或攻击动作在限制生效前已执行完成。
3. **组合式攻击仍有失败案例**：分数流策略为了保留能力而收紧包络，可能依旧允许某些未见过的参数值；组合目标的跨调用语义无法通过单参数包络完整捕获。
4. **自适应攻击下能力有限**：对已知策略且无法获取 IRM 反馈的更强敌手，部分攻击成功（如 A1、B1、C1b/C2b），需通过扩展 B、强制包络规范化等方式弥补。
5. **可扩展性问题**：Workspace 套件的 Min-Cut 计算耗时可达 12.56 s，在技能数量更多、图更复杂的真实场景下可能存在性能瓶颈。
6. **未考虑多智能体协调、直接越狱、训练时后门等威胁**：防御范围限定在工具调用边界，无法阻止不调用任何工具的社会工程类攻击。
7. **实验资源信息缺失**：未报告训练/推理所用 GPU 型号与数量等资源信息，復现成本不透明。
8. **对策略正确性的敏感性**：当包络由精确变为保守时，能力保留率从 93.21% 降至 82.50%；若包络完全无约束，则必须删除所有工具，显著影响实用性。
