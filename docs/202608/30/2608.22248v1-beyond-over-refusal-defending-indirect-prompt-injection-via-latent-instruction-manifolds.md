## 摘要
大型语言模型（LLM）已被整合到复杂的生态系统中（例如代码代理），而间接提示注入（IPI）攻击已成为其安全部署的关键障碍。攻击者利用LLM无法区分“指令”和“数据”的特性，通过恶意注入的指令来操纵LLM。然而，现有的防御面临难以解决的安全-效用权衡：大多数防护措施要么产生高延迟，要么遭受严重的过度拒绝。在本文中，我们首先通过理论和实证证据证明，LLM可以从本质上将指令与数据分离。受此启发，我们提出了AEGIS（自适应集成防护以抵御注入屏蔽）。AEGIS提取指令敏感投影仪来识别恶意指令，并利用统一的跨层共识机制聚合网络深度中的拓扑不同信号。实证评估表明，与基线相比，AEGIS在针对启发式和基于优化的攻击方面实现了显著的检测性能，凸显了其缓解IPI的潜力。代码可在 https://github.com/xaddwell/AEGIS 获取。

## Abstract
Large Language Models (LLMs) have been integrated into complex ecosystems (e.g., Code Agents), while Indirect Prompt Injection (IPI) attacks have emerged as critical barriers to their safe deployment. Attackers exploit LLMs' indistinguishability between "instructions" and "data" to manipulate LLMs via maliciously injected instructions. Existing defenses, however, face an intractable safety-utility trade-off: most guardrails either incur high latency or suffer from severe over-refusal. In this paper, we first demonstrate that LLMs can separate instruction from data intrinsically with both theoretical and empirical evidence. Inspired by this insight, we propose AEGIS (Adaptive Ensemble Guard for Injection Shielding). AEGIS extracts instruction-sensitive projectors to identify malicious instructions and leverages a Unified Multi-Layer Consensus mechanism that aggregates topologically distinct signals across the network depth. Empirical evaluations show that AEGIS achieves remarkable detection performance against both heuristic and optimization-based attacks compared to baselines, highlighting its potential to mitigate IPI. Code is available at https://github.com/xaddwell/AEGIS

## 2. 论文提出的方法论

### 2.1 核心思想
- 基于线性表示假说，将激活向量建模为语义分量的叠加：`h(l) = h_K(l) + α·h_Iadv(l) + ε`，其中 `α ∈ {0,1}` 表示是否存在攻击。检测任务即寻找投影函数，在限制误报率的同时最大化检测概率。
- 利用 Fisher 判别准则，寻找一类投影方向 `w*`，使指令类投影后与知识类质心的距离尽可能大、指令类内部的方差尽可能小，从而锁定指令的稳定语义内核而非表面措辞变化。

### 2.2 关键技术细节

- **指令敏感投影器（Instruction-Sensitive Projector）**：
  - 优化目标：`w* = argmax_w (w^T(μI - μK))^2 / (w^T ΣI w)`
  - 闭式解：`w* ∝ ΣI^{-1}(μI - μK)`
  - 其中 `ΣI^{-1}` 作为“语义聚焦器”，降低指令可变维度（词汇变体）的权重，提高指令紧凑且与知识区分度高的维度权重。使用 Ledoit-Wolf 收缩估计协方差矩阵。

- **分布感知的安全阈值校准**：
  - 基于良性知识集的投影统计量设定决策边界：`b = -Q_{1-β}({w*^T h | h ∈ D_benign})`
  - 通过选择分位数 `β`，确保检测器在良性输入上至多触发 `β` 比例，从而数学上锚定误报率，避免过度拒绝。

- **统一多层共识机制（Unified Multi-Layer Consensus）**：
  - 将多个网络层视为“委员会”，对每层投影分数进行变换后聚合：`S_ens(x) = Σ_{l∈L_vote} φ_l(S_l(x))`，最终决策 `ŷ = I(S_ens(x) ≥ Γ)`。
  - 支持两种模式：
    - **Hard Voting**：`φ_hard(s) = I(s > b_l)`，`S_ens` 为投票数，`Γ` 为共识法定人数。
    - **Soft Voting**：`φ_soft(s) = (s - μ_benign(l)) / σ_b(l)`，对分数进行标准化后累加，可在低信噪比下通过线性累积信号实现对微弱扰动的检测。

### 2.3 理论保证

- **集成误报率误差上界**（Hard Voting）：利用 Hoeffding 不等式，若单层误报率 ≤ β 且层间近似独立，则系统级 FPR 满足：
  `Q_ens ≤ exp(-2|L_vote| (Γ/|L_vote| - β)^2)`
  表明只要共识门槛高于单层噪声底，误报率随层数指数衰减。
- **潜在鲁棒半径**：对每个受监控层定义到决策超平面的最小距离 `R_l(x) = b_l - S_l(x)`。集成鲁棒半径为所有层半径的 Γ 阶统计量 `R_ens(x) = R_(Γ)` — 任何范数小于该值的潜在扰动都无法翻转集成判定。这从几何上保证了“集体防线不取决于最弱层，而取决于第 Γ 层”。

- **攻击类型**：覆盖 8 种 IPI 攻击：

## 6. 论文的主要结论与发现

- **结论 1**：LLM 在本质上能够分离指令与数据，且这种分离性由训练范式决定。PCA 可视化显示（图 1）：经过指令微调的模型（Instruct 版）在隐藏状态中指令与知识表征的可分性远高于基础模型（Base 版）。

- **结论 3**：AEGIS 对启发式和基于优化的攻击都表现出强泛化能力，而传统方法往往偏向一端（过度拒绝或漏检）。例如，AttTracker FPR 高达 38.57%，DeBERTa 对 Naive Attack 的 FNR 高达 99.51%。

- **结论 6**：AEGIS 在 Llama3、Llama3.1、Qwen3 上均保持一致的跨模型高性能（ACC > 97%，FPR < 5%），说明其利用了通用结构不变量，而非特定架构的过拟合。

## 7. 优点

- **理论驱动**：从谱不对称性假设出发，同时给出 Fisher 判别投影、FPR 指数上界（Hoeffding 不等式）和潜在鲁棒半径（顺序统计量）的正式推导，使方法具有可解释性与理论保障。
- **安全-效用平衡新范式**：通过分布感知阈值锚定 + 多层共识，在保持高召回的同时将误报率降至可忽略水平，直接针对“过度拒绝”痛点。

- **数据高效性**：仅用极少样本即可达到最优性能，便于实际部署。
- **辅助分析充分**：包含逐层敏感性、超参数热图、样本量收敛曲线与 ROC 等深入分析，验证了方法的内在机制。

## 8. 不足与局限

- **白盒依赖**：AEGIS 需要访问模型内部隐藏状态，无法直接用于闭源商业模型（如 GPT-4、Claude API），限制了其应用范围。
- **层独立性假设**：Hoeffding 误差上界基于层间近似独立假设，而真实 LLM 层间存在依赖，导致理论界可能偏乐观（论文中已明确指出）。
- **计算开销非零**：AEGIS 在推理时增加了约 120 ms 延迟与额外的 GPU 内存占用，在超高通量实时场景下可能成为瓶颈。
- **实验规模限制**：评估模型最高仅 8B 参数，未验证更大模型（如 70B/数百 B）；实验在单卡 A100 上进行，未反映多卡或分布式环境。
- **训练数据偏差风险**：校准语料仅含 200 个样本，虽证明效率，但若部署环境的知识分布与校准集差异过大，`w*` 与阈值可能失配——论文未评估跨分布迁移的鲁棒性。
- **基线公平性问题**：部分基线（如 PIShield）为了与 AEGIS 对齐被限制为 200 个训练样本，与其原始配置不符，虽然在“数据效率”维度上对比合理，但在“绝对性能”对比中可能低估了这些基线；同样，所有基线阈值基于 1% FPR 调参，可能对某些方法不最优。
- **缺少端到端“任务成功率”评测**：论文仅聚焦于检测性能（ACC/FPR/FNR）与延迟，未评估同一输入上被拦截后模型在真实 RAG/Agent 任务中的最终任务完成率或语义保留程度。
