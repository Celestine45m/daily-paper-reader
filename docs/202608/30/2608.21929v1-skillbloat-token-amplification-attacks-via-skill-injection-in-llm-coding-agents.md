## 摘要
代理技能为编码代理提供了任务特定的指令、脚本和资源，但也创建了一个可信的指令渠道，可能被滥用以超越常规的安全攻击。本文研究通过技能注入实现令牌放大：一种经济资源滥用威胁，其中恶意技能导致代理消耗比正常任务执行所需多得多的令牌。我们提出了SkillBloat，一个两阶段框架，首先在多种放大机制中筛选包含多种攻击类型条件的库，然后通过LLM引导的全文文档技能重写来优化最强候选。在真实世界的技能基准测试中，SkillBloat在多个编码代理目标配置下实现了5.4184倍至10.1455倍的平均最佳放大。消融研究表明，第二阶段的细化循环持续优于仅第一阶段攻击类型筛选的平均最佳放大，证明迭代优化在初始攻击类型选择之外提供了额外收益。这些结果表明，技能生态系统暴露了一个实用的资源放大攻击面，该攻击面与现有的面向安全的技能投毒正交。

## Abstract
Agent skills extend coding agents with task-specific instructions, scripts, and resources, but they also create a trusted   instruction channel that can be abused beyond conventional security attacks. This paper studies token amplification through   skill injection: an economic resource-abuse threat in which a malicious skill causes an agent to consume substantially more   tokens than needed for normal task execution. We present SkillBloat, a two-phase framework that first screens a library of   diverse attack-type conditions across multiple amplification mechanisms and then refines the strongest candidate through   LLM-guided full-document skill rewriting. Evaluated on a real-world skill benchmark, SkillBloat achieves 5.4184x-10.1455x   average best amplification across multiple coding-agent target configurations. An ablation shows that the second-stage   refinement loop consistently improves average best amplification over Phase 1 attack-type screening alone, demonstrating   that iterative optimization provides additional benefit beyond initial attack-type selection. These results show that skill   ecosystems expose a practical resource-amplification attack surface that is orthogonal to existing security-oriented skill   poisoning.

### 1. 论文的核心问题与整体含义

- **背景**：大语言模型（LLM）已从文本生成器发展为能够规划、调用工具、多步推理的自主代理，尤其是编码代理（如 Claude Code、OpenAI Codex CLI、Gemini CLI）可自主完成软件工程任务。为提升可扩展性，这类系统引入“Agent Skills”机制，即把任务特定的指令、脚本和资源打包成模块化的 `SKILL.md` 文件，代理在触发后将其加载进上下文并执行。
- **核心问题**：技能机制创造了一个“可信指令通道”，可被恶意技能滥用，造成 **令牌放大（Token Amplification）**，即让代理在执行正常任务时消耗远超必要的 token，导致经济资源滥用。这与传统技能投毒（数据泄露、权限提升、文件篡改、后门注入）在目标上根本不同，属于一类未被系统研究的攻击面。
- **威胁含义**：
  1. 技能被代理赋予高特权与高信任，恶意指令难以与合法冗长指令区分；
  2. 攻击可以保持任务完成度，提升隐蔽性；
  3. 不触发面向安全的传统检测器（针对数据外泄或系统入侵的检测）。

### 2. 论文提出的方法论

#### 2.1 核心思想

- 提出 **SkillBloat** 框架，通过两阶段流水线优化恶意技能文档：
  - **Phase 1（筛选）**：构建多种攻击类型条件，分别作用于不同的放大机制，在目标代理上逐一测试，选出单次放大最强的攻击类型；
  - **Phase 2（优化）**：以 Phase 1 的获胜攻击类型为起点，通过 LLM 引导的迭代反馈循环，不断重写完整技能文档，使放大效果逐步增强。

#### 2.2 关键技术细节

- **攻击类型库 Z**：包含 15 种条件，覆盖三类放大机制：
  - 输出膨胀（Verbose Output、Self-Debate、Task Decomposition）
  - 工具驱动放大（Tool Pollution、Pipeline Bloat、File I/O Loop、Error Retry）
  - 上下文放大（Input Bloat、Calibration Loop、Context Time Bomb）
  - 另有混合重写条件（Prerequisite Injection、Description Injection、Code Import Injection、Verification Injection、Multi-Point Injection），用于把放大指令嵌入文档不同位置。
- **Tool-Fusion Attack Agent**：给定攻击类型，从工具清单选择一组工具（每个工具有显示名、描述、文件名、命令行参数和集成提示），构造结构化 Prompt；攻击模型（默认 gpt-5.5）据此生成完整的 `SKILL.md`，要求保留原任务内容、把工具调用包装为常规 QA/验证步骤、使用专业术语、控制输出长度范围。
- **全文档重写而非片段插入**：使恶意指令与原始内容风格一致，并将放大逻辑分散到文档多个部分，提高自然度与原任务的适配性。
- **Phase 1 公式**：  
  \(z^* = \arg\max_{z_k\in Z} R_{total}(z_k)=\arg\max_{z_k\in Z} C_{adv}(t,\hat{s}_k)/C_{base}(t,s)\)  
  其中 \(C_{base}\) 为良性技能基线 token 消耗，\(\hat{s}_k\) 为攻击类型生成的对抗技能。
- **Phase 2 循环**：
  - **Refine**：攻击模型基于原始技能、上一版本、累积反馈历史及工具集，重新生成改进后的 `SKILL.md`；系统提示根据上一轮诊断的失败类型动态调整。
  - **Execute**：部署到目标代理，记录执行轨迹（放大率、任务完成状态、响应）。
  - **Diagnose**：Failure Analyzer 将结果归类为失败类型并生成结构化反馈，加入反馈历史。
  - 最终从 Phase 1 全部候选和 Phase 2 所有记录中选择总放大率最高的技能作为最终输出。
