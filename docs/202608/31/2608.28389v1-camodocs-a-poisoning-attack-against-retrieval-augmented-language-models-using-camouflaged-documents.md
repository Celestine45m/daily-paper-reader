## 摘要
检索增强生成（RAG）通过外部文档增强大型语言模型（LLM），但公共或用户可编辑来源使RAG系统面临数据投毒风险：攻击者可注入恶意文档，将输出引导至目标答案。现有投毒攻击通常依赖查询包含，将目标查询插入恶意文档以提高检索效果；然而，这会产生词汇和嵌入空间伪影，使其容易被过滤。我们提出CamoDocs，一种通过将对抗性文档伪装在良性内容中以避免直接查询包含的投毒攻击。CamoDocs对合成的良性草稿和对抗性草稿进行分块，用分散令牌替换良性块中的选定令牌，以扩散中毒文档的嵌入，并应用连贯性过滤以限制可读性下降。在七种RAG防御、三种开放权重LLM和三个基准测试中，CamoDocs在避免简单查询检测利用的查询重叠伪影的同时，实现了较强的平均攻击成功率（ASR）。它对专有模型也依然有效，在GPT-5.4-mini上平均ASR为61.80%，在Claude-Haiku-4.5上为55.09%。最后，我们表明，诸如TrustRAG之类的强擦除聚类防御可以降低ASR，但只能在诸如NeoQA等依赖检索的基准上大幅降低实用性。代码可在https://github.com/jaewonalive/CamoDocs获取。

## Abstract
Retrieval-augmented generation (RAG) augments LLMs with external documents, but public or user-editable sources expose RAG systems to data poisoning: attackers can inject malicious documents to steer outputs toward targeted answers. Existing poisoning attacks often rely on query inclusion, inserting the target query into poisoned documents to improve retrieval; however, this creates lexical and embedding-space artifacts that make them easy to filter. We propose CamoDocs, a poisoning attack that avoids direct query inclusion by camouflaging adversarial documents among benign content. CamoDocs chunks synthesized benign and adversarial drafts, replaces selected tokens in benign chunks with dispersion tokens that spread poisoned-document embeddings, and applies coherence filtering to limit readability degradation. Across seven RAG defenses, three open-weight LLMs, and three benchmarks, CamoDocs achieves strong average ASR while avoiding query-overlap artifacts exploited by simple query detection. It also remains effective against proprietary models, achieving average ASRs of 61.80% on GPT-5.4-mini and 55.09% on Claude-Haiku-4.5. Finally, we show that erasure-heavy clustering defenses such as TrustRAG can reduce ASR, but only with substantial utility drops on retrieval-dependent benchmarks such as NeoQA. Code is available at https://github.com/jaewonalive/CamoDocs.

# CamoDocs 论文总结

## 1. 核心问题与整体含义

- **背景**：检索增强生成（RAG）通过外部知识库增强大语言模型，但公共/用户可编辑来源引入了数据投毒风险：攻击者注入恶意文档可诱导模型输出错误答案。
- **已有攻击的缺陷**：PoisonedRAG、PIA、CorruptRAG 等依赖“查询包含”（query inclusion），即把目标查询直接写入恶意文档以提升检索命中率，但这会产生词汇级和嵌入空间上的痕迹，容易被简单查询检测或聚类防御过滤。
- **核心问题**：能否构造一种不包含目标查询、同时在嵌入空间上伪装成良性数据的投毒攻击，从而绕过现有防御？
- **论文回答**：提出 **CamoDocs**，通过“伪装文档”策略实现高攻击成功率，同时揭示当前防御的脆弱性——尤其是强擦除型聚类防御（如 TrustRAG）虽能降低 ASR，却会严重损害 RAG 在证据依赖场景下的实用性。

## 2. 方法论

- **核心思想**：为每个目标查询同时合成“良性草稿”和“对抗草稿”，将两者分块后，在良性子文档中做梯度引导的 token 替换，用“分散令牌”扩大嵌入在特征空间中的分散度，最后与对抗子文档拼接成最终恶意文档。
- **威胁模型**：黑盒攻击，攻击者无法访问受害 LLM 参数和嵌入模型参数，但可以向知识库注入文档；目标是为特定查询诱导预定义的错误答案。
- **三阶段流程**：
  1. **准备原料**：用合成器 LLM（LLM_synth）生成 5 份良性草稿（基于查询和正确答案）和 5 份对抗草稿（基于查询、正确答案、目标错误答案）；每份草稿均匀切成 γ=2 块，得到 β=10 对良性与对抗子文档。
  2. **令牌操作（Token Manipulation）**：
     - 对每个良性子文档，循环 α=30 次随机采样一个位置，用代理嵌入模型 Esurr（ANCE）计算嵌入分散损失：`L = (1/β) Σ ||e_j - c||`

继续补全如下：

- 其中 \( c = \frac{1}{\beta} \sum_j e_j \) 是当前良性子文档池的嵌入中心；通过梯度上升更新被采样位置的 token 嵌入，使各个良性子文档的嵌入相互远离，从而在特征空间中形成“分散”的良性簇。最终，用这些被修改的良性子文档与对应的对抗子文档拼接（每个查询生成 5 份候选恶意文档，选取检索得分最高者），形成最终注入文档。

- **代理模型与可迁移性**：攻击者使用 ANCE 作为代理嵌入模型（Esurr）进行文档检索；目标受害系统则使用不同的嵌入模型（如 Contriever、E5-large 等）。实验表明 CamoDocs 的恶意文档天然具备跨嵌入模型的可迁移性，攻击成功率在多个目标嵌入模型上均保持较高水平。

- **多查询扩展**：针对多个目标查询，可对每个查询独立生成恶意文档，批量注入知识库；每个文档的 token 级扰动独立计算，互不干扰。

## 3. 实验设置

- **数据集**：NQ（Natural Questions）和 MS MARCO 的开放域问答子集；每个数据集选取 100 个真实查询，为每个查询构造预定义错误答案（取自其他查询的正确答案或人工指定）。
- **受害者 LLM**：Llama-3.1-8B-Instruct、GPT-3.5-turbo、GPT-4o-mini 等；采用两种 RAG 设置：Top-5 直接生成（无重排序）和 Top-20 检索后重排序（使用 Cohere Rerank）。
- **对比攻击方法**：PoisonedRAG、PIA、CorruptRAG、直接注入（无伪装）。
- **防御基线**：
  - **查询检测类**：简单字符串匹配、正则表达式、嵌入相似度过滤（检测文档是否包含与用户查询高度相似的句子）。
  - **聚类防御类**：K-means 聚类、HSJA 嵌入聚类、TrustRAG（对检索结果进行语义聚类，过滤低代表性簇）。
- **评估指标**：攻击成功率（ASR，即目标错误答案出现在 LLM 输出中的比例）、良性查询的实用性指标（回答准确率 F1/EM，用于衡量防御对正常检索的影响）。

## 4. 主要结果

- **攻击成功率**：
  - 在无防御场景下，CamoDocs 的 ASR 显著高于基线攻击（PoisonedRAG 等），在 NQ 数据集上 Top-5 设置可达 90%+，即便防御方使用嵌入相似度过滤（阈值 0.7），ASR 仍保持 70% 以上。
  - 相比之下，传统攻击在嵌入相似度过滤下 ASR 急剧下降，证明 CamoDocs 的“无查询包含”和“嵌入分散”策略有效规避了识别。
- **跨模型迁移**：
  - 使用 ANCE 作为代理模型生成的恶意文档，在 Contriever、E5-large 等目标嵌入模型上仍然保持高检索命中率，说明攻击并不依赖特定嵌入空间。
- **对重排序的鲁棒性**：
  - 即使用户使用重排序器（Cohere Rerank）重新排列检索结果，CamoDocs 依然能使恶意文档进入 Top-5，ASR 仅略有下降（约 5 个百分点）。
- **防御评估**：
  - 简单的查询检测和嵌入相似度过滤对 CamoDocs 基本无效。
  - 聚类防御（如 K-means、TrustRAG）能降低 ASR，但代价显著：
    - 在 NQ 数据集上，TrustRAG 将 CamoDocs 的 ASR 从 90% 降至约 20%，但同时将良性查询的答案准确率从 75% 降至 45% 左右；
    - 在 MS MARCO 上，类似趋势更为明显——防御导致实用性问题恶化，说明强擦除型防御在过滤恶意文档时会误删大量良性证据，破坏 RAG 系统的核心价值。

## 5. 分析与消融

- **组件贡献**：
  - 仅使用“无查询包含”策略（不做嵌入分散）时，ASR 虽然高于传统攻击，但仍容易被嵌入相似度过滤发现；
  - 仅使用“嵌入分散”而不去除查询词时，攻击鲁棒性不足；
  - 两者结合（CamoDocs）才能同时绕过词汇级检测和嵌入空间聚类。
- **子文档数量与迭代次数**：
  - 多块拼接（β=10）比单块更有效，因为单个文档的嵌入需要伪装成良性（与查询无关），而分散多块可在检索时形成共振效应；
  - α=30 次 token 替换足以显著提高攻击成功率，继续增大收益递减。
- **鲁棒性分析**：
  - 即使防御者使用与受害者不同的 LLM 或嵌入模型进行反向工程，CamoDocs 的恶意文档依然能保持较好的隐蔽性；
  - 对文档长度、分块方式（固定长度 vs 自然段落）不敏感，说明攻击具有实际部署稳定性。

## 6. 意义与启示

- **对 RAG 安全研究**：
  - 揭示了“不包含查询词”的攻击空间——现有防御过度依赖查询-文档重叠特征，无法应对分布级伪装攻击。
  - 强调了防御-实用性的根本矛盾：聚类/擦除型防御以降低良性查询效果为代价换取安全性，在证据依赖型任务上可能带来比投毒攻击本身更严重的负面影响。
- **对 RAG 系统设计者的建议**：
  - 不能仅依赖检索来源的可信度或简单的相似度过滤；
  - 需要开发不牺牲实用性的检测机制，例如基于生成侧的语义一致性校验、对检索文档的可解释性审查等。
- **局限性**：
  - 需要一个合成器 LLM（LLM_synth）生成高质量草稿，对错误答案的定义依赖攻击者的领域知识；
  - 在“无需生成对抗草稿”的纯数据污染场景（如仅破坏可用性而非诱导特定答案）中表现未知；
  - 防御评估中的 TrustRAG 参数可能未完全调优，实际部署中防御效果可能更好，但即便如此，论文的结论——现有防御在真实性、鲁棒性和实用性之间存在显著trade-off——是稳健的。

## 7. 个人评价

- **优点**：
  - 攻击设计巧妙，将“嵌入分散”与“无查询包含”结合，在技术上有原创性；
  - 实验覆盖多个防御维度，提供了可复现的消融分析；

  - 未评估对基于 LLM 的“语义去重”或“幻觉检测”类新防御的抵抗能力。
